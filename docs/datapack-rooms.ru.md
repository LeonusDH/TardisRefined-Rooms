# Помещения из датапаков

[English](datapack-rooms.md) · **Русский** · [Содержание](README.ru.md)

Датапак может добавить в каталог свои помещения. Помещение — это один или два шаблона структуры (по одному на уровень) и JSON-файл. Готовый пример лежит в [`examples/datapack/tardis_rooms_example`](../examples/datapack/tardis_rooms_example). Скопируйте папку в `datapacks` мира, и среди комнат появится «Library». В его [README](../examples/datapack/README.ru.md) пример разобран по полям.

## Файлы

- `data/<namespace>/structure/<путь>.nbt` — шаблоны. Их можно сохранить структурным блоком или командой экспорта, см. [Экспорт помещения](#экспорт-помещения).
- `data/<namespace>/tardis_rooms/rooms/<имя>.json` — описание помещения.

Пространство имён `tardis_rooms` занято встроенными помещениями, используйте своё.

```json
{
  "name": "Library",
  "description": "Bookshelves along the walls",
  "group": "room",
  "structure": "example:rooms/library",
  "entrance": {"x": 0, "z": 0, "side": "south"},
  "exits": [{"x": 0, "z": 0, "side": "north"}],
  "control_block": [11, 1, 15],
  "rotatable": true
}
```

| Поле | Обязательно | Что значит |
|---|---|---|
| `name` | да | Название в каталоге: строка или текстовый компонент, например `{"translate": "..."}` |
| `description` | нет | Подсказка в каталоге |
| `group` | нет | `corridor`, `room` или `special`. Без него помещение попадает в группу «Из датапаков», которая скрыта, пока пуста |
| `structure` | да | Id шаблона или список из двух id для помещения на два уровня (сначала нижний) |
| `entrance` | да | Проход, которым помещение пристраивается к узлу роста. Должен быть на нижнем уровне |
| `exits` | нет | Остальные проходы. В каждом появится узел роста, проход соединится с соседним или закроется заглушкой |
| `control_block` | нет | Где стоит блок управления помещением, в координатах шаблона. Без него — ближе к середине пола |
| `removable` | нет | Блоки этого помещения, которые никогда не мешают его убрать, см. ниже |
| `rotatable` | нет | По умолчанию `true`. `false` — помещение не поворачивается и строится только от узлов, к которым уже обращено входом |

Проход записывается как `{"x": ..., "z": ..., "side": ..., "floor": ...}`: модуль внутри шаблона (считая с 0), стена (`north`, `south`, `west` или `east`) и уровень (`0` — нижний, по умолчанию).

## Блоки, которые уходят вместе с помещением

`removable` — блоки, которые уходят вместе с помещением, что бы в них ни было, и поэтому никогда не мешают его убрать или заменить. Запись — место или описание:

- `[x, y, z]` — блок в координатах шаблона нижнего уровня, `[x, y, z, этаж]` — другого уровня. Считается только этот самый блок: такой же блок, поставленный игроком в другом месте помещения, по-прежнему придётся сначала опустошить. Местами отмечайте обычные блоки, например кафедру или сундук.
- Строка — любой такой блок в этом помещении, где бы он ни стоял, в том числе поставленный игроками; как записывать — на странице [Записи блоков](block-entries.ru.md). Строкой отмечайте блоки, которые игрок вряд ли поставит сам, например голову с определённым профилем: `"minecraft:player_head{profile:{name:\"MHF_Question\"}}"`.

```json
"removable": [[11, 2, 11], [3, 2, 5, 1], "minecraft:player_head{profile:{name:\"MHF_Question\"}}"]
```

Всё, что лежит в этих блоках, пропадёт вместе с помещением, поэтому отмечайте только блоки, в которых игроки не должны хранить вещи.

Места поворачиваются вместе с помещением, когда оно разворачивается к узлу, как `control_block`, в том числе блоки, перенесённые отражением полосы у прохода (см. ниже). Места и описания запоминаются вместе с помещением при росте, так что изменения датапака потом не меняют правила для уже построенных помещений.

## Требования к шаблону

- Ширина и глубина кратны 24 блокам (одному модулю). Высота уровня — не больше 27 блоков. У помещения на два уровня оба уровня одного размера.
- Проход — проём во внешней стене на блоках 8–10 вдоль стены, считая от северного или западного угла модуля, на высоте 2–4 блока от низа шаблона. Эти блоки должны быть воздухом. Ряд выше, на высоте 5, может быть аркой.
- Сохраняйте шаблон вместе с воздухом. Пустые места шаблона оставят то, что было там раньше.
- Шаблон ставится низом на пол уровня: слои 0–1 — пол, как у встроенных помещений.

Проходы на 8–10 стоят не посередине стены, поэтому при повороте к узлу часть проходов попадает на 13–15. Тогда аддон отражает полосу этой стены: блоки 8–15 вдоль неё, на всю высоту уровня и на 3 блока вглубь. Проход возвращается на 8–10. Декор, который нельзя отражать, держите вне этой полосы или поставьте `"rotatable": false`.

Помещение на два уровня растёт вверх от уровня узла, поэтому с верхнего уровня его не построить. На верхнем уровне доступно только 18 блоков высоты.

Ошибки пишутся в лог сервера при загрузке датапаков, по строке на ошибку, начиная с `Datapack room <id>:`. Помещение с ошибками пропускается.

## Экспорт помещения

`/tardis_rooms export <id>` сохраняет помещение, в котором вы стоите, как помещение для датапака. Подходит любое помещение: встроенное, из датапака или перестроенное вручную. Нужны права оператора.

- Получается готовый датапак в `<мир>/tardis_rooms_export` с шаблонами, JSON и `pack.mcmeta`. Перенесите его в папку `datapacks` мира и выполните `/reload`.
- Помещение сохраняется как стоит, без поворота. Вход — сторона, которой оно пристроено к узлу.
- Узлы роста, заглушки и их фонари становятся воздухом. Блок управления заменяется соседним блоком пола, а его место записывается в `control_block`. Интерфейсы ТАРДИС тоже становятся воздухом, чтобы их ID не повторялись.
- Сохранить можно только прямоугольное помещение на одном уровне или на двух соседних.

Если убрать датапак, уже построенные из него помещения останутся на месте. Они показываются как «Неизвестное помещение», их по-прежнему можно заменить или удалить.
