# Записи блоков

[English](block-entries.md) · **Русский** · [Содержание](README.ru.md)

Блоки, которые уходят вместе с помещением, что бы в них ни было, и поэтому никогда не мешают его убрать или заменить, указываются в двух местах:

- в файле `config/tardis_rooms/removable_with_room.toml` — для всех помещений ([Настройки](configuration.ru.md#блоки-которые-уходят-вместе-с-помещением));
- в поле `removable` помещения из датапака — только для этого помещения ([Помещения из датапаков](datapack-rooms.ru.md#блоки-которые-уходят-вместе-с-помещением)).

Оба понимают одни и те же строки:

| Запись | Подходит |
|---|---|
| `minecraft:lectern` | этот блок |
| `#minecraft:banners` | блоки с тегом |
| `mekanism:*_cable`, `*:*_sign` | id блоков, где `*` — любой текст |
| `@mekanism` | все блоки мода (альтернативно: `mekanism:*`) |
| `minecraft:player_head{SkullOwner:{Name:"MHF_Question"}}` | блок с данными, как в `/execute if block` |
| `#minecraft:candles[lit=false]` | блок или тег со свойствами, как в `/execute if block` |

## Подробнее

- **Пространство имён.** Id без пространства имён означает `minecraft`: `lectern` — это `minecraft:lectern`, `*_bed` — `minecraft:*_bed`.
- **`*`** — любой текст, в том числе пустой, и может стоять несколько раз: `*:*_sign` — все таблички всех модов. `*` удобна для групп, у которых нет тега, например для всех кабелей мода.
- **`@мод`** — то же, что `мод:*`.
- **Свойства блока** — в квадратных скобках: `minecraft:chest[type=single]`. Неуказанное свойство может быть любым.
- **Данные** — в фигурных скобках, в формате SNBT, как в командах. Подходят, если в данных блока есть указанные поля; остальные могут быть любыми. Список подходит, если каждый указанный элемент нашёлся в списке блока: `minecraft:chest{Items:[{id:"minecraft:diamond"}]}` — сундук, в котором есть алмазы, что бы ещё в нём ни лежало.
- Свойства и данные можно указывать и для тега: `#minecraft:banners{Patterns:[{Pattern:"cre"}]}`.

## Ошибки

- В датапаке неправильно записанная запись попадает в лог сервера при загрузке датапаков — `Datapack room <id>: removable "...": <причина>`, — и помещение пропускается. Теги в этот момент ещё не загружены, поэтому несуществующий тег попадёт в лог позже, при первой проверке помещения: `Room <n> (<id>): removable: skipping ...`.
- В `removable_with_room.toml` записи проверяются при первом использовании, когда теги уже загружены, и заново после изменения файла. Неправильная запись пропускается с предупреждением в логе `tardis_rooms/removable_with_room.toml: skipping ...`, остальные работают.

## Осторожно

Всё, что лежит в подходящем блоке, пропадёт вместе с помещением. Не указывайте блоки, в которых игроки хранят вещи. С `@мод` и `*` будьте особенно осторожны: у модов техники почти каждый блок хранит предметы, жидкости или энергию. Интерфейс ТАРДИС мешает убрать помещение всегда, что бы ни было указано в записях.
