# TARDIS Refined: Rooms

[English](README.md) · **Русский**

Аддон для [Tardis Refined](https://github.com/Whocraft/TardisRefined) на Minecraft 1.21.1 (NeoForge и Fabric). Вместо бесконечных процедурных ARS-коридоров интерьер ТАРДИС строите вы сами, помещение за помещением, как в классическом моде TARDIS для 1.7.10.

## Возможности

### Рост интерьера

- Интерьер разбит на сетку модулей на пяти этажах: этаж хаба, три под ним и один над ним.
- В переходах стоят **узлы роста**. Нажмите на узел звуковой отвёрткой, и откроется каталог помещений и коридоров. Выберите вариант, и ТАРДИС вырастит его за стеной. Рост бесплатный.
- В каталоге есть план каждого варианта сверху и **карта этажа**: что уже занято, где хаб, где строить нельзя и куда встанет новое помещение.
- У каждого помещения есть **блок управления помещением**. Через него отвёрткой помещение можно заменить или убрать. Помещение не уберётся, если в нём остались контейнеры или механизмы или если через него связаны другие помещения.
- Переход, который никуда не ведёт, закрывает **заглушка прохода**. Если соседнее место освободится, заглушка станет новым узлом роста.
- Датапаки могут добавлять свои помещения, а любое построенное помещение можно сохранить как такое. Подробнее — в разделе [Свои помещения через датапак](#свои-помещения-через-датапак).

### Интерфейс ТАРДИС

Блок, который передаёт ресурсы между связанными интерфейсами: между помещениями или между интерьером и внешним миром рядом с оболочкой.

- Интерфейсы с одинаковым ID связаны. Отвёрткой можно скопировать ID с одного интерфейса и вставить в другой.
- У интерфейса есть направление (вход или выход) и выбор, что он передаёт: предметы, жидкости, энергию, редстоун, химикаты Mekanism и сеть ME из AE2 (последние два — только на NeoForge).
- Интерфейс ничего не хранит и передаёт всё сразу, поэтому скорость зависит от подключённых труб и механизмов.
- Каждую сторону можно перевести в режим **«По умолчанию»**, **«Вставлять»** или **«Забирать»**. Это делается в объёмном окне настройки сторон или ключом из любого мода. Стороны «Вставлять» и «Забирать» работают с обычными сундуками, без труб.
- Shift + ПКМ ключом снимает интерфейс сразу в инвентарь вместе с настройками.
- Ключи определяются по метке предметов `tardis_rooms:wrenches`: в неё входят общие метки ключей и ключ Tech Reborn. Сборка может добавить свои ключи датапаком.

### Другие изменения в Tardis Refined

- Процедурные ARS-комнаты и коридоры отключены, в том числе случайные коридоры над хабом.
- Хаб TR упрощён: остаются центр со шлюзом, смотровая Ока Гармонии и два коротких перехода к первым узлам роста. Остальное становится местом для строительства. Это происходит только в хабе, где ещё никто ничего не строил.
- У внутренних дверей и высоких оболочек ТАРДИС появляется невидимая верхняя половина: на верх двери можно навести прицел и нажать, и туда нельзя поставить блок.

Необязательная совместимость. Каждая включается, только если установлен соответствующий мод:

| Мод | NeoForge | Fabric | Что даёт |
|---|---|---|---|
| Mekanism 10.7+ | ✓ | — | Химикаты через интерфейс |
| Applied Energistics 2 19.2+ | ✓ | — | Сеть ME через интерфейс; картой памяти можно копировать и вставлять ID интерфейса |
| Jade 15.10+ | ✓ | ✓ | Состояние интерфейса во всплывающей подсказке |
| Team Reborn Energy 4.1+ | — | ✓ | Энергия через интерфейс. Его вкладывают в себя большинство технических модов на Fabric; на NeoForge энергия работает и так |

Поддержку Mekanism, AE2 и Jade можно выключить в настройках.

## Свои помещения через датапак

Датапак может добавить в каталог свои помещения. Помещение — это один или два шаблона структуры (по одному на уровень) и JSON-файл. Готовый пример лежит в [`examples/datapack/tardis_rooms_example`](examples/datapack/tardis_rooms_example). Скопируйте папку в `datapacks` мира, и среди комнат появится «Library».

### Файлы

- `data/<namespace>/structure/<путь>.nbt` — шаблоны. Их можно сохранить структурным блоком или командой экспорта, о ней ниже.
- `data/<namespace>/tardis_rooms/rooms/<имя>.json` — описание помещения.

Пространство имён `tardis_rooms` занято встроенными помещениями, используйте своё.

```json
{
  "name": "Library",
  "description": "Bookshelves along the walls",
  "group": "room",
  "structure": "example:rooms/library",
  "entrance": {"x": 0, "z": 0, "side": "south"},
  "exits": [{"x": 0, "z": 0, "side": "north"}],
  "control_block": [11, 1, 15],
  "rotatable": true
}
```

| Поле | Обязательно | Что значит |
|---|---|---|
| `name` | да | Название в каталоге: строка или текстовый компонент, например `{"translate": "..."}` |
| `description` | нет | Подсказка в каталоге |
| `group` | нет | `corridor`, `room` или `special`. Без него помещение попадает в группу «Из датапаков», которая скрыта, пока пуста |
| `structure` | да | Id шаблона или список из двух id для помещения на два уровня (сначала нижний) |
| `entrance` | да | Проход, которым помещение пристраивается к узлу роста. Должен быть на нижнем уровне |
| `exits` | нет | Остальные проходы. В каждом появится узел роста, проход соединится с соседним или закроется заглушкой |
| `control_block` | нет | Где стоит блок управления помещением, в координатах шаблона. Без него — ближе к середине пола |
| `rotatable` | нет | По умолчанию `true`. `false` — помещение не поворачивается и строится только от узлов, к которым уже обращено входом |

Проход записывается как `{"x": ..., "z": ..., "side": ..., "floor": ...}`: модуль внутри шаблона (считая с 0), стена (`north`, `south`, `west` или `east`) и уровень (`0` — нижний, по умолчанию).

### Требования к шаблону

- Ширина и глубина кратны 24 блокам (одному модулю). Высота уровня — не больше 27 блоков. У помещения на два уровня оба уровня одного размера.
- Проход — проём во внешней стене на блоках 8–10 вдоль стены, считая от северного или западного угла модуля, на высоте 2–4 блока от низа шаблона. Эти блоки должны быть воздухом. Ряд выше, на высоте 5, может быть аркой.
- Сохраняйте шаблон вместе с воздухом. Пустые места шаблона оставят то, что было там раньше.
- Шаблон ставится низом на пол уровня: слои 0–1 — пол, как у встроенных помещений.

Проходы на 8–10 стоят не посередине стены, поэтому при повороте к узлу часть проходов попадает на 13–15. Тогда аддон отражает полосу этой стены: блоки 8–15 вдоль неё, на всю высоту уровня и на 3 блока вглубь. Проход возвращается на 8–10. Декор, который нельзя отражать, держите вне этой полосы или поставьте `"rotatable": false`.

Помещение на два уровня растёт вверх от уровня узла, поэтому с верхнего уровня его не построить. На верхнем уровне доступно только 18 блоков высоты.

Ошибки пишутся в лог сервера при загрузке датапаков, по строке на ошибку, начиная с `Datapack room <id>:`. Помещение с ошибками пропускается.

### Экспорт помещения

`/tardis_rooms export <id>` сохраняет помещение, в котором вы стоите, как помещение для датапака. Подходит любое помещение: встроенное, из датапака или перестроенное вручную. Нужны права оператора.

- Получается готовый датапак в `<мир>/tardis_rooms_export` с шаблонами, JSON и `pack.mcmeta`. Перенесите его в папку `datapacks` мира и выполните `/reload`.
- Помещение сохраняется как стоит, без поворота. Вход — сторона, которой оно пристроено к узлу.
- Узлы роста, заглушки и их фонари становятся воздухом. Блок управления заменяется соседним блоком пола, а его место записывается в `control_block`. Интерфейсы ТАРДИС тоже становятся воздухом, чтобы их ID не повторялись.
- Сохранить можно только прямоугольное помещение на одном уровне или на двух соседних.

Если убрать датапак, уже построенные из него помещения останутся на месте. Они показываются как «Неизвестное помещение», их по-прежнему можно заменить или удалить.

## Настройки

`config/tardis_rooms/common.toml`:

| Параметр | По умолчанию | Что делает |
|---|---|---|
| `disableProceduralRooms` | `true` | Не генерировать процедурные ARS-комнаты и коридоры Tardis Refined |
| `simplifyHub` | `true` | Оставить в хабе TR только обязательные части (см. выше) |
| `debug` | `false` | Писать в лог подробности: что аддон пристроил, заменил или убрал |
| `compat.mekanism` / `compat.ae2` / `compat.jade` | `true` | Включение и выключение отдельных совместимостей |

В клиентских настройках задаётся угол рычага двери на консоли Factory.

## Сборка

Нужен JDK 21. Mekanism, AE2, Jade и Team Reborn Energy Gradle скачает из Maven сам. Tardis Refined из PR #618 нужно собрать локально:

1. Соберите Tardis Refined из PR:
   ```sh
   git clone https://github.com/Whocraft/TardisRefined.git
   cd TardisRefined
   git fetch origin pull/618/head
   git checkout FETCH_HEAD
   ./gradlew :forge:downloadAssets   # только в первый раз, вместе со следующей строкой
   ./gradlew :forge:runData          # создаёт модели, рецепты и переводы; когда сообщит, что файлы записаны, закройте его
   ./gradlew :forge:build
   ./gradlew :fabric:build
   ```
2. Скопируйте оба jar в папку `libs/` этого проекта:
   - `forge/build/libs/forge-tardis_refined-mc1.21.1-v2.1.6.jar` под именем `tardis_refined-neoforge-1.21.1-2.1.6-pr618.jar`;
   - `fabric/build/libs/fabric-tardis_refined-mc1.21.1-v2.1.6.jar` под именем `tardis_refined-fabric-1.21.1-2.1.6-pr618.jar`.

   Чтобы оставить исходные имена, вместо этого поменяйте `tr_neoforge_jar` и `tr_fabric_jar` в `gradle.properties`.
3. Соберите аддон:
   ```sh
   ./gradlew build
   ```
   Jar появятся в `neoforge/build/libs/` и `fabric/build/libs/`. На Windows то же самое делает `build.bat`: он сам находит JDK 21 и пишет вывод в `build.log`.

Общий для обоих загрузчиков код лежит в `common/`; в `neoforge/` и `fabric/` — только то, что у них отличается.

> [!NOTE]
> Java считает `!` в пути разделителем внутри путей к jar, поэтому, если в пути к папке проекта есть `!`, игра (датаген, тестовые запуски) не запускается. `build.bat` обходит это, подключая папку как временный диск; если запускаете Gradle вручную, используйте путь без `!`.

Английский перевод генерируется из `TRoomsText` командой `./gradlew :neoforge:runData`. Остальные языки — обычные файлы в `common/src/main/resources/assets/tardis_rooms/lang/`.
